01 — SectionDesktop Apps with Electron

An Electron app is three separate programs wearing one window. Getting the boundary between them right is the entire skill — and getting it wrong is how desktop apps become remote-code-execution exploits.

ProcessRunsCan it touch the filesystem?
MainNode.js — no DOMYes. Owns windows, files, child processes.
PreloadNode + DOM, sandboxedYes, but must expose only a tiny, deliberate API.
RendererChromium — the web pageNo. And it must stay that way.
main.js — the composition root javascript 
const { app, BrowserWindow, ipcMain, dialog } = require('electron');
const path = require('node:path');

function createWindow() {
  const window = new BrowserWindow({
    width: 1100,
    height: 720,
    backgroundColor: '#0b0b0d',
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,      // non-negotiable
      nodeIntegration: false,      // non-negotiable
      sandbox: true
    }
  });

  window.loadFile('index.html');
}

app.whenReady().then(() => {
  createWindow();

  // macOS keeps the app alive with no windows open
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit();
});
!
The two flags that matter

nodeIntegration: true hands the renderer full Node access. Any XSS in your page — a malicious npm package, an injected script, a remote image with a bad URL — becomes arbitrary code execution on the user's machine. contextIsolation: true plus nodeIntegration: false is the default in modern Electron precisely because this went wrong so often.

The preload bridge

The preload script is the only place where the two worlds meet. It should expose a small, explicit, named API — never ipcRenderer itself.

preload.js javascript 
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  // Request / response — returns a promise in the renderer
  openFile: () => ipcRenderer.invoke('file:open'),
  save: (data) => ipcRenderer.invoke('file:save', data),
  run: (data) => ipcRenderer.invoke('runner:run', data),
  stop: () => ipcRenderer.invoke('runner:stop'),

  // Main -> renderer push. Note the callback is wrapped, never passed through.
  onOutput: (callback) => {
    ipcRenderer.on('runner:output', (_event, payload) => callback(payload));
  },

  onState: (callback) =>
    ipcRenderer.on('runner:state', (_event, state) => callback(state))
});

// What NOT to do:
//   contextBridge.exposeInMainWorld('ipc', { send: ipcRenderer.send })
// That exposes the raw IPC channel — the renderer can now invoke
// any handler in your main process by name.
main.js — handling requests javascript 
let window;

function send(channel, data) {
  // The window may already be gone — a stale send throws
  if (window && !window.isDestroyed()) {
    window.webContents.send(channel, data);
  }
}

ipcMain.handle('file:open', async () => {
  const result = await dialog.showOpenDialog({
    properties: ['openFile'],
    filters: [{ name: 'JavaScript', extensions: ['js', 'mjs', 'cjs'] }]
  });

  if (result.canceled || result.filePaths.length === 0) return null;

  return fs.readFile(result.filePaths[0], 'utf8');
});

ipcMain.handle('file:save', async (_event, data) => {
  // Validate before trusting ANYTHING from the renderer
  if (typeof data?.code !== 'string') {
    throw new Error('Invalid JavaScript source.');
  }
  return saveFile(data);
});

Sandboxing the renderer

Everything arriving over IPC is untrusted input, even though you wrote the renderer. A filename is the classic attack path — ../../.ssh/authorized_keys is a perfectly valid string.

destination.js — validate, then build the path javascript 
function destination(name) {
  if (
    typeof name !== 'string' ||
    name !== path.basename(name) ||              // no directory components
    /[<>:"/\\|?*\x00-\x1f]/.test(name) ||        // no separators or control chars
    !/\.(js|mjs|cjs)$/i.test(name)               // extension allow-list
  ) {
    throw new Error('Enter a valid .js, .mjs, or .cjs filename.');
  }

  return path.join(directory, name);
}
i
Four checks, in order of importance

1. Is it even a string? 2. basename(name) === name is the single cleanest traversal guard — it rejects anything with a path separator. 3. An extension allow-list, because you're about to execute this. 4. Character whitelist for the remaining platform-specific traps.

runner.js — spawning a child process safely javascript 
const { spawn } = require('node:child_process');

function launch(file) {
  // NOTE: no `shell: true`, and the command is an array.
  // With a shell, any metacharacter in `file` becomes a command injection.
  const child = spawn(process.execPath, [file], {
    cwd: path.dirname(file),
    env: { ...process.env, FORCE_COLOR: '0' },
    stdio: ['pipe', 'pipe', 'pipe'],
    windowsHide: true
  });

  child.stdout.on('data', (chunk) =>
    send('runner:output', { text: chunk.toString(), error: false }));

  child.stderr.on('data', (chunk) =>
    send('runner:output', { text: chunk.toString(), error: true }));

  child.on('error', (error) =>
    send('runner:output', { text: `${error.message}\n`, error: true }));

  child.on('close', (code) => send('runner:state', code === 0 ? 'Done' : 'Failed'));

  return child;
}

// Graceful shutdown — never leave orphans behind
app.on('before-quit', () => {
  if (activeRun) activeRun.kill();
});
  • Main, preload and renderer are separate processes with separate trust levels.
  • contextIsolation: true and nodeIntegration: false, always.
  • Expose named functions on the bridge — never raw ipcRenderer.
  • Validate every IPC payload before it touches the filesystem or a shell.

02 — SectionReal-Time Audio & State Machines

Microphone APIs fire events asynchronously and in no guaranteed order. Users hit stop while speech is being transcribed. Devices vanish mid-session. Without structure, you end up with callbacks writing into a UI that has already moved on.

The fix used in production voice apps is an explicit state machine: a frozen set of states, a table of legal transitions, and a single function that is the only way state can change.

vad-state.js javascript 
// Object.freeze means a typo throws instead of creating a new state
export const VAD_STATE = Object.freeze({
  IDLE: 'idle',
  INITIALIZING: 'initializing',
  LISTENING: 'listening',
  SPEECH_DETECTED: 'speech_detected',
  PAUSED: 'paused',
  STOPPING: 'stopping',
  ERROR: 'error'
});

// The transition table IS the documentation.
const VALID_TRANSITIONS = {
  [VAD_STATE.IDLE]: [VAD_STATE.INITIALIZING],
  [VAD_STATE.INITIALIZING]: [
    VAD_STATE.LISTENING, VAD_STATE.STOPPING, VAD_STATE.ERROR, VAD_STATE.IDLE
  ],
  [VAD_STATE.LISTENING]: [
    VAD_STATE.SPEECH_DETECTED, VAD_STATE.PAUSED, VAD_STATE.STOPPING, VAD_STATE.ERROR
  ],
  [VAD_STATE.SPEECH_DETECTED]: [
    VAD_STATE.LISTENING, VAD_STATE.STOPPING, VAD_STATE.ERROR
  ],
  [VAD_STATE.PAUSED]: [
    VAD_STATE.LISTENING, VAD_STATE.STOPPING, VAD_STATE.ERROR
  ],
  [VAD_STATE.STOPPING]: [VAD_STATE.IDLE, VAD_STATE.ERROR],
  [VAD_STATE.ERROR]: [VAD_STATE.IDLE, VAD_STATE.INITIALIZING]
};
transition.js — one door in javascript 
const subscribers = new Set();
let session = null;

function subscribe(callback) {
  subscribers.add(callback);
  // Return the unsubscribe function — the caller cannot forget the pair
  return () => subscribers.delete(callback);
}

function notify(state) {
  subscribers.forEach((callback) => {
    try {
      callback(state);
    } catch (error) {
      // One broken subscriber must not break the audio pipeline
      console.error('state subscriber threw:', error);
    }
  });
}

function transitionTo(next) {
  if (!session) return false;

  const current = session.state;
  const allowed = VALID_TRANSITIONS[current] || [];

  if (!allowed.includes(next)) {
    console.warn(`[VAD] illegal transition ${current} → ${next}`);
    return false;                 // rejected, state unchanged
  }

  session.state = next;
  notify(next);
  return true;
}
i
Why this beats boolean flags

With isRecording, isStarting and isPaused you eventually get a combination that means nothing — three booleans is eight states, and you'll never define them all. A single state variable with a transition table makes impossible states unrepresentable, and the illegal-transition warning finds your bug the first time it happens instead of the hundredth.

Session tokens — killing stale callbacks

Here is the bug this pattern exists for: the user stops recording, you tear down the audio graph, and then a MediaRecorder event from the previous session fires and writes into your brand-new recording.

session-token.js javascript 
let counter = 0;
const makeToken = () => `vad_${Date.now().toString(36)}_${(++counter).toString(36)}`;

async function start() {
  // A new token makes every callback from the old session a no-op
  const token = makeToken();
  session = { token, state: VAD_STATE.IDLE, onData: [], lastSpeechAt: 0 };

  transitionTo(VAD_STATE.INITIALIZING);

  const instance = await createDetector({
    onSpeechStart: () => {
      if (session?.token !== token) return;    // stale — drop it
      session.lastSpeechAt = Date.now();
      transitionTo(VAD_STATE.SPEECH_DETECTED);
    },

    onSpeechEnd: (audio) => {
      if (session?.token !== token) return;    // stale — drop it

      // Validate the audio before forwarding it anywhere
      if (audio.length < MIN_SAMPLES) return;
      if (rms(audio) < MIN_RMS_THRESHOLD) return;   // silence, not speech

      session.onData.forEach((fn) => fn(audio));
      transitionTo(VAD_STATE.LISTENING);
    }
  });

  transitionTo(VAD_STATE.LISTENING);
  return instance;
}

async function stop(instance) {
  transitionTo(VAD_STATE.STOPPING);

  // Invalidate first, clean up second — never the other way round
  session = null;
  await instance?.destroy();

  transitionTo(VAD_STATE.IDLE);
}

// Root mean square — a cheap "is there actually sound here?" test
function rms(samples) {
  let sum = 0;
  for (let i = 0; i < samples.length; i++) sum += samples[i] * samples[i];
  return Math.sqrt(sum / samples.length);
}

const MIN_SAMPLES = 8000;        // ~0.5s at 16kHz
const MIN_RMS_THRESHOLD = 0.005; // below this is silence
!
Invalidate before you clean up

The order in stop() matters. If you tear down the audio graph first, the teardown itself fires events that now pass the token check and run against a half-destroyed session. Set session = null first so every in-flight callback is already stale.

  • Model async lifecycles as an explicit state machine with a transition table.
  • Frozen state constants turn typos into errors instead of phantom states.
  • Session tokens make callbacks from a previous run inert.
  • Always provide a synchronous way to unsubscribe, and clean up in the right order.

03 — SectionCanvas & the Render Loop

Animation is requestAnimationFrame, not setInterval. The timer callback knows nothing about the display; rAF fires once per frame, in sync with the browser, and is throttled automatically when the tab is hidden.

why not setInterval text 
setInterval(render, 16)   ->  fires while the tab is hidden, on the wrong beat,
                              and produces a dropped frame whenever it collides
                              with layout or paint.

requestAnimationFrame      ->  fires once per painted frame, pauses when hidden,
                              and hands you the frame timestamp for free.
loop.js javascript 
function startAnimation(canvas, update, draw) {
  const context = canvas.getContext('2d');
  let previous = performance.now();
  let rafId = null;
  let running = true;

  function size() {
    const dpr = Math.min(window.devicePixelRatio || 1, 2);

    // Scale the backing store, then scale the context back down.
    // Without this, everything is blurry on a retina display.
    canvas.width = Math.floor(canvas.clientWidth * dpr);
    canvas.height = Math.floor(canvas.clientHeight * dpr);

    context.setTransform(dpr, 0, 0, dpr, 0, 0);
  }

  function frame(now) {
    // Seconds since the last frame — this is what makes motion
    // independent of the display's refresh rate.
    const delta = Math.min((now - previous) / 1000, 0.05);
    previous = now;

    update(delta);
    draw(context, delta);

    if (running) rafId = requestAnimationFrame(frame);
  }

  size();
  window.addEventListener('resize', size);

  document.addEventListener('visibilitychange', () => {
    if (document.hidden) {
      running = false;
      if (rafId) cancelAnimationFrame(rafId);
      rafId = null;
    } else {
      running = true;
      previous = performance.now();     // don't jump after a pause
      rafId = requestAnimationFrame(frame);
    }
  });

  rafId = requestAnimationFrame(frame);

  return () => {
    running = false;
    if (rafId) cancelAnimationFrame(rafId);
    window.removeEventListener('resize', size);
  };
}

Delta time — the difference between smooth and broken

wrong-vs-right.js javascript 
// WRONG — moves a fixed amount per frame.
// 144Hz monitors run the simulation 2.4x faster than 60Hz ones.
function updateBroken() {
  agent.x += 2;
}

// RIGHT — velocity is per second, so the result looks identical everywhere
function updateCorrect(delta) {
  agent.x += agent.vx * delta;      // vx is pixels per second
}

// The clamp matters: after the tab has been backgrounded, delta can be
// dozens of seconds and everything teleports off screen.
const safeDelta = Math.min((now - previous) / 1000, 0.05);

A boids flock, in the essentials

Three rules per particle — separation, alignment, cohesion — and a flock appears. It's the classic demonstration that simple local rules produce complex global behaviour.

boids.js javascript 
const PERCEPTION = 60;
const MAX_SPEED = 120;      // pixels per second

function stepFlock(boids, delta) {
  for (const boid of boids) {
    let sepX = 0, sepY = 0;      // push away from neighbours
    let aliX = 0, aliY = 0;      // match neighbours' heading
    let cohX = 0, cohY = 0;      // drift toward neighbours' centre
    let neighbours = 0;

    for (const other of boids) {
      if (other === boid) continue;

      const dx = boid.x - other.x;
      const dy = boid.y - other.y;
      const distanceSq = dx * dx + dy * dy;

      if (distanceSq > PERCEPTION * PERCEPTION || distanceSq === 0) continue;

      neighbours++;
      sepX += dx / distanceSq;     // inverse square: closer pushes harder
      sepY += dy / distanceSq;
      aliX += other.vx;
      aliY += other.vy;
      cohX += other.x;
      cohY += other.y;
    }

    if (neighbours > 0) {
      aliX /= neighbours;  aliY /= neighbours;
      cohX = cohX / neighbours - boid.x;
      cohY = cohY / neighbours - boid.y;
    }

    boid.vx += sepX * 1.5 + aliX * 1.0 + cohX * 0.01;
    boid.vy += sepY * 1.5 + aliY * 1.0 + cohY * 0.01;

    // Clamp to a maximum speed, then integrate
    const speed = Math.hypot(boid.vx, boid.vy) || 1;
    if (speed > MAX_SPEED) {
      boid.vx = (boid.vx / speed) * MAX_SPEED;
      boid.vy = (boid.vy / speed) * MAX_SPEED;
    }

    boid.x += boid.vx * delta;
    boid.y += boid.vy * delta;
  }
}

// The whole flock drawn in ONE path — one fill call, not 200.
function drawFlock(context, boids) {
  context.beginPath();
  for (const boid of boids) {
    context.moveTo(boid.x + 3, boid.y);
    context.arc(boid.x, boid.y, 3, 0, Math.PI * 2);
  }
  context.fillStyle = '#ffffff';
  context.fill();
}
!
The nested loop is O(n²)

Every boid checks every other boid. At 200 boids that's 40,000 distance checks per frame — fine. At 5,000 it's 25 million, and your frame budget is 16ms. Real implementations use a spatial grid: bucket boids into cells the size of the perception radius and only compare within adjacent cells, which brings it close to linear.

i
Allocate outside the loop

Creating objects or arrays inside a per-frame function means the garbage collector runs during your animation — which is exactly when a pause is most visible. Reuse scratch arrays and mutate boids in place, as above, rather than building new objects each frame.

  • requestAnimationFrame syncs with the display and pauses when hidden.
  • Multiply all motion by delta time, and clamp the delta.
  • Scale the canvas backing store by devicePixelRatio or it looks blurry.
  • Keep per-frame work allocation-free, and batch your draw calls.

04 — SectionArchitecting a Node Daemon

A daemon is a long-running process that samples the world, decides something, acts, and remembers what worked. The architecture below is the difference between a script and a system that survives a week of uptime.

the layers text 
  adapters    adb, http clients, filesystem     — talk to the outside world
     |
  monitors    cpu, memory, thermal, battery      — turn raw data into samples
     |
  history     rolling window of recent samples   — gives you trends, not just now
     |
  decision    weighted score + safety gates      — should we act at all?
     |
  plugins     the actual actions, each scoring   — do the thing, record the result
     |
  learning    EMA + circuit breaker per plugin   — a plugin that fails gets benched
     |
  daemon      wires it together and schedules    — the composition root

The composition root

Nothing constructs its own dependencies. The daemon creates everything once, in dependency order, and hands each piece what it needs. That's what makes any single monitor testable in isolation.

daemon.js javascript 
class DeviceOptimizerDaemon {
  constructor(rootDir = path.resolve(__dirname, '..')) {
    this.rootDir = rootDir;
    this.bus = new EventBus();
    this.running = false;
  }

  async init() {
    this.config = await loadConfig(this.rootDir);
    this.adb = new Adb(this.config.adbPath || 'adb');

    // Bounded memory: history cannot grow forever
    this.history = new RollingHistory(this.config.historyLimit);

    this.logger = new MetricsLogger(this.rootDir, this.config.dataDir);
    await this.logger.init();

    this.learning = new LearningStore(
      this.rootDir,
      this.config.dataDir,
      this.config.minimumUsefulGainMb,
      this.config.pluginFailureDisableThreshold
    );
    await this.learning.init();

    // Each monitor is a thin adapter with one job
    this.monitors = {
      memory: new MemoryMonitor(this.adb),
      cpu: new CpuMonitor(this.adb),
      thermal: new ThermalMonitor(this.adb),
      battery: new BatteryMonitor(this.adb),
      foreground: new ForegroundMonitor(this.adb)
    };

    // Injected, not imported — a test can pass fakes
    this.decisionEngine = new DecisionEngine(this.config, this.history, this.learning);
    this.optimizationEngine = new OptimizationEngine({
      monitors: this.monitors,
      bus: this.bus,
      learning: this.learning
    });
  }
}

An event bus decouples the pieces

event-bus.js javascript 
class EventBus extends EventEmitter {
  emitSafe(event, payload) {
    this.emit(event, payload);
  }

  async emitAsync(event, payload) {
    // Collect async listeners so the caller can await all of them
    const listeners = this.listeners(event);
    await Promise.all(listeners.map((fn) => fn(payload)));
  }
}

// A monitor announces what happened; it does not know who cares.
bus.emitSafe('pressure:high', { usedPercent: 82, score: 74 });

// The logger, the UI bridge and the optimizer each subscribe independently —
// add a fourth consumer later and none of the existing code changes.
bus.on('pressure:high', (data) => metrics.write(data));
bus.on('pressure:high', (data) => uiBridge.push(data));

A decision engine with safety gates

The interesting part isn't the score — it's the gates. Acting on a hot or low-battery device makes things worse, no matter how much memory you'd reclaim.

decision-engine.js javascript 
decide(sample) {
  const used = sample.memory.summary.usedPercent;
  const growth = this.history.growth((item) => item.memory.summary.usedPercent);
  const cpu = sample.cpu.loadPercent;

  const thermalHigh = sample.thermal.risk === 'HIGH'
    || sample.battery.temperatureC >= this.config.maximumBatteryTemperatureC;

  const batteryLow = sample.battery.level >= 0
    && sample.battery.level < this.config.minimumBatteryPercent;

  const userActive = sample.foreground.active;

  // A weighted score beats a single threshold — growth and free memory
  // both matter, and they matter by different amounts.
  const pressureScore =
      used
    + Math.max(0, growth * 1.2)                              // trending up is worse
    + Math.max(0, sample.storage.usedPercent - 90) * 0.4     // near-full disk
    - (sample.memory.summary.availableMb > 1800 ? 8 : 0);    // plenty free

  // Hard gates: any one of these vetoes the action outright
  const allowed =
      cpu <= this.config.maximumCpuForOptimizationPercent
    && !thermalHigh
    && !batteryLow
    && !userActive;

  let recommendation = 'observe';
  if (pressureScore > 68 && allowed) recommendation = 'optimize';
  if (used <= this.config.targetUsedMemoryPercent) recommendation = 'target-met';
  if (!allowed) recommendation = 'defer-risk';

  return {
    usedPercent: used,
    memoryGrowth: growth,
    pressureScore,
    allowed,
    recommendation,
    reasons: { cpu, thermalHigh, batteryLow, userActive }
  };
}
i
Return the reasons, not just the verdict

reasons: { cpu, thermalHigh, batteryLow, userActive } is the most valuable line in the function. Next month, when someone asks "why didn't it optimise?", the log answers the question directly instead of sending you back into the code.

Learning, with a circuit breaker

learning-store.js javascript 
class LearningStore {
  constructor(rootDir, dataDir, minimumUsefulGainMb, failureThreshold) {
    this.path = path.join(rootDir, dataDir, 'learning.json');
    this.minimumUsefulGainMb = minimumUsefulGainMb;
    this.failureThreshold = failureThreshold;
    this.state = {};
  }

  async init() {
    try {
      this.state = JSON.parse(await fs.readFile(this.path, 'utf8'));
    } catch (error) {
      if (error.code !== 'ENOENT') throw error;   // a corrupt file is a real problem
      this.state = {};                            // first run is not
    }
  }

  // Circuit breaker: enough consecutive failures and we stop trying
  isDisabled(plugin) {
    return (this.state[plugin]?.consecutiveFailures || 0) >= this.failureThreshold;
  }

  score(plugin) {
    const item = this.state[plugin];
    if (!item) return 0;
    return (item.averageGainMb || 0) - (item.consecutiveFailures || 0) * 20;
  }

  async record(plugin, gainMb) {
    const item = this.state[plugin] ||
      { runs: 0, usefulRuns: 0, consecutiveFailures: 0, averageGainMb: 0 };

    item.runs += 1;

    // Exponentially weighted moving average — no need to store every sample.
    // The running mean stays correct without an array that grows forever.
    item.averageGainMb += (gainMb - item.averageGainMb) / item.runs;

    if (gainMb >= this.minimumUsefulGainMb) {
      item.usefulRuns += 1;
      item.consecutiveFailures = 0;      // success resets the breaker
    } else {
      item.consecutiveFailures += 1;
    }

    this.state[plugin] = item;
    await this.persist();
  }

  async persist() {
    await fs.mkdir(path.dirname(this.path), { recursive: true });
    await fs.writeFile(this.path, JSON.stringify(this.state, null, 2), 'utf8');
  }
}
!
The moving average is doing real work

avg += (value - avg) / runs computes the exact running mean in constant space. Storing every sample to average them later means an array that grows for the lifetime of the process — a slow leak in a daemon that runs for months.

Delta sampling — you can only measure change

cpu-monitor.js javascript 
class CpuMonitor {
  constructor(adapter) {
    this.adapter = adapter;
    this.previous = null;
  }

  async sample() {
    // Independent reads run concurrently, not one after the other
    const [stat, freq] = await Promise.all([
      this.adapter.shell(['cat', '/proc/stat']),
      this.adapter.shell(['sh', '-c', 'cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq'])
    ]);

    const current = parseCpuLine(stat.stdout);

    // The FIRST sample has nothing to compare against — report 0, not a fake number
    const loadPercent = this.previous && current
      ? busyPercent(this.previous, current)
      : 0;

    this.previous = current;

    return {
      loadPercent,
      frequenciesKhz: freq.ok
        ? freq.stdout.split(/\s+/).map(Number).filter(Number.isFinite)
        : []
    };
  }
}

// /proc/stat counters only ever increase, so the busy ratio is the DELTA
function busyPercent(prev, curr) {
  let total = 0;
  let idle = 0;

  for (let i = 0; i < Math.min(prev.length, curr.length); i++) {
    const delta = curr[i] - prev[i];
    total += delta;
    if (i === 3 || i === 4) idle += delta;    // idle + iowait
  }

  return total > 0 ? ((total - idle) / total) * 100 : 0;
}

safe-paths.js javascript 
const path = require('node:path');

const BASE = '/srv/uploads';

function safePath(untrustedName) {
  // 1. Type check — it might not even be a string
  if (typeof untrustedName !== 'string') throw new Error('invalid name');

  // 2. basename() strips every directory component.
  //    "../../etc/passwd" becomes "passwd", and we then verify nothing changed.
  if (untrustedName !== path.basename(untrustedName)) {
    throw new Error('path traversal attempt');
  }

  // 3. Resolve and confirm the result is still inside BASE.
  //    Belt and braces: catches symlinks and platform quirks basename misses.
  const resolved = path.resolve(BASE, untrustedName);
  if (!resolved.startsWith(BASE + path.sep)) {
    throw new Error('resolved outside the base directory');
  }

  return resolved;
}
!
Command injection is one boolean away

exec(`ls ${userInput}`) runs through a shell, so ; rm -rf ~ in the input is a command. Use execFile/spawn with an argument array and no shell: true — then the input is passed as a literal argument and never interpreted. If you truly need a shell, pass user data through an environment variable.

Scanning for leaked secrets

Most credential leaks are committed accidentally — a key pasted into a config file, a token left in a build output, a secret shipped in client-side JavaScript. A pattern-based scanner catches them before they reach a repository.

  { name: 'Stripe Secret Key',     risk: 'HIGH',   re: /\b(sk_(?:live|test)_[0-9a-zA-Z]{24,99})\b/g },
  { name: 'Stripe Publishable Key',risk: 'LOW',    re: /\b(pk_(?:live|test)_[0-9a-zA-Z]{24,99})\b/g },

scan.js javascript 
// Known library internals that look like secrets but aren't.
// Without this, every React bundle reports "__SECRET_INTERNALS" as a hit.
const WHITELIST = ['__SECRET_INTERNALS', 'swiper-', 'fb_mobile_', 'accessible-megamenu'];

function scanText(text, sourceLabel) {
  const findings = [];
  const seen = new Set();      // dedupe: the same key in ten bundles is one finding

  // Every regex is global and reused, so reset lastIndex before each scan
  for (const signature of SECRET_SIGNATURES) {
    signature.re.lastIndex = 0;

    let match;
    while ((match = signature.re.exec(text)) !== null) {
      const value = match[1] ?? match[0];

      if (WHITELIST.some((entry) => value.includes(entry))) continue;

      const key = `${signature.name}:${value}`;
      if (seen.has(key)) continue;
      seen.add(key);

      findings.push({
        name: signature.name,
        risk: signature.risk,
        source: sourceLabel,
        // ALWAYS redact. A scanner that logs the secret has just leaked it
        // somewhere new — into a report, a console, a CI artefact.
        preview: value.slice(0, 4) + '…' + value.slice(-4),
        index: match.index
      });
    }
  }

  return findings;
}

// Report by severity, never by value
const report = scanText(bundleSource, 'dist/app.js');
const highRisk = report.filter((finding) => finding.risk === 'HIGH');

console.log(`${highRisk.length} high-risk findings in ${report.length} total`);
highRisk.forEach((f) => console.log(`  ${f.name} at ${f.source} ${f.preview}`));
i
The five habits that prevent most of this

1. Validate at the boundary, not deep inside. 2. Allow-list what's permitted instead of blocking what isn't. 3. Never build a shell command from a string. 4. Redact secrets in logs and error messages — including stack traces and request dumps. 5. Assume client-side code is public, because it is; a "hidden" API key in a bundle is a published API key.

  • Every boundary is an attack surface: HTTP, IPC, files, storage, user content.
  • basename plus a resolve containment check stops path traversal.
  • Use spawn/execFile with argument arrays — never a shell string.
  • Scan for secret signatures, whitelist library noise, and always redact the value.

06 — SectionReact Patterns That Scale

React punishes two things: unhandled render errors and unnecessary re-renders. These are the patterns that address both.

Error boundaries — a crash should not blank the page

ErrorBoundary.tsx typescript 
import { Component, type ReactNode } from 'react';

interface State {
  error: Error | null;
  stack: string;
}

// Error boundaries MUST be class components — there is no hook equivalent
export class ErrorBoundary extends Component<{ children: ReactNode }, State> {
  state: State = { error: null, stack: '' };

  // Called during render, so it must be pure — just return the new state
  static getDerivedStateFromError(error: Error): Partial<State> {
    return { error };
  }

  // Called after the commit — side effects belong here
  componentDidCatch(error: Error, info: { componentStack?: string }) {
    console.error('render crash:', error, info.componentStack);
    reportToTelemetry({ message: error.message, stack: info.componentStack });
    this.setState({ stack: info.componentStack ?? '' });
  }

  render() {
    if (!this.state.error) return this.props.children;

    return (
      <div role="alert">
        <h2>Something went wrong</h2>
        <p>Your data is safe. Try again.</p>
        <pre>{String(this.state.error)}</pre>
        <button onClick={() => this.setState({ error: null, stack: '' })}>
          Retry
        </button>
      </div>
    );
  }
}
!
What boundaries do and don't catch

They catch errors during render, in lifecycle methods, and in constructors below them. They do not catch errors in event handlers, in setTimeout callbacks, in async code, or in the boundary itself. A rejected promise in a useEffect sails straight past — handle those where they happen.

A hook for async data

useAsync.js javascript 
import { useState, useEffect } from 'react';

function useAsync(load, deps = []) {
  const [state, setState] = useState({ status: 'loading', data: null, error: null });

  useEffect(() => {
    // The same stale-callback problem from audio, solved the same way.
    // Without this flag, a fast re-render can let a slow request win.
    let cancelled = false;

    setState({ status: 'loading', data: null, error: null });

    load()
      .then((data) => {
        if (!cancelled) setState({ status: 'success', data, error: null });
      })
      .catch((error) => {
        if (!cancelled) setState({ status: 'error', data: null, error });
      });

    // The cleanup sets the flag — React calls it on unmount and on dep change
    return () => {
      cancelled = true;
    };
  }, deps);

  return state;
}

// Usage
function UserCard({ id }) {
  const { status, data, error } = useAsync(() => fetchUser(id), [id]);

  if (status === 'loading') return <p>Loading…</p>;
  if (status === 'error') return <p role="alert">{error.message}</p>;
  return <h2>{data.name}</h2>;
}
!
The deps array is not optional

Passing [] when you meant [id] gives you an effect that runs once and then shows stale data forever. As a rule: every value from the component body that the effect reads must be in the dependency array. The ESLint exhaustive-deps rule exists because this is the most common React bug in existence.

Animation that doesn't re-render

Driving an animation through React state means a full reconcile on every frame. Use a ref and mutate the DOM directly — React renders the container once, and the animation never touches the virtual DOM.

ParticleField.jsx javascript 
import { useRef, useEffect } from 'react';

export function ParticleField({ count = 60 }) {
  const canvasRef = useRef(null);

  useEffect(() => {
    const canvas = canvasRef.current;
    const ctx = canvas.getContext('2d');
    const dpr = Math.min(window.devicePixelRatio || 1, 2);

    canvas.width = canvas.clientWidth * dpr;
    canvas.height = canvas.clientHeight * dpr;
    ctx.setTransform(dpr, 0, 0, dpr, 0, 0);

    const dots = Array.from({ length: count }, () => ({
      x: Math.random() * canvas.clientWidth,
      y: Math.random() * canvas.clientHeight,
      vx: (Math.random() - 0.5) * 20,
      vy: (Math.random() - 0.5) * 20
    }));

    let rafId;

    function frame(now) {
      const delta = Math.min((now - previous) / 1000, 0.05);
      previous = now;

      ctx.clearRect(0, 0, canvas.clientWidth, canvas.clientHeight);
      for (const dot of dots) {
        dot.x += dot.vx * delta;
        dot.y += dot.vy * delta;
      }
      ctx.fill();
      rafId = requestAnimationFrame(frame);
    }

    let previous = performance.now();
    rafId = requestAnimationFrame(frame);

    // Cleanup: cancel the frame AND stop any pending work
    return () => cancelAnimationFrame(rafId);
  }, [count]);          // re-runs only if count changes

  // One render. Zero re-renders per frame.
  return <canvas ref={canvasRef} className="particle-field" />;
}

Every useEffect should answer: what do I undo?

Subscribe → unsubscribe. Start a timer → clear it. Attach a listener → remove it. Open a connection → close it. If you can't name the cleanup, the effect is probably leaking. In React 18 StrictMode every effect runs twice in development specifically to surface the ones that aren't idempotent.

  • Error boundaries are class components and catch render errors only.
  • Hooks that fetch need a cancellation flag and a correct dependency array.
  • Drive animation with refs and rAF, never with state.
  • lazy + Suspense turns routes into on-demand chunks.

07 — SectionTesting Real Systems

Testing a pure function is easy. The value is in testing the parts that actually break: state machines, normalisation of shape-shifting API responses, and anything involving timers.

Testing a state machine

A transition table is a specification — so test it like one. The most valuable tests assert that illegal transitions are refused.

state-machine.test.js javascript 
import test from 'node:test';
import assert from 'node:assert/strict';
import { createRecorder, VAD_STATE } from './recorder.js';

test('walks the happy path', () => {
  const recorder = createRecorder();

  assert.equal(recorder.state, VAD_STATE.IDLE);
  recorder.transitionTo(VAD_STATE.INITIALIZING);
  recorder.transitionTo(VAD_STATE.LISTENING);
  recorder.transitionTo(VAD_STATE.SPEECH_DETECTED);

  assert.equal(recorder.state, VAD_STATE.SPEECH_DETECTED);
});

test('refuses an illegal transition and keeps the current state', () => {
  const recorder = createRecorder();
  recorder.transitionTo(VAD_STATE.INITIALIZING);
  recorder.transitionTo(VAD_STATE.LISTENING);

  // idle is not reachable directly from listening
  const accepted = recorder.transitionTo(VAD_STATE.IDLE);

  assert.equal(accepted, false);
  assert.equal(recorder.state, VAD_STATE.LISTENING, 'state must not change');
});

test('notifies subscribers and stops after unsubscribe', () => {
  const recorder = createRecorder();
  const seen = [];

  const unsubscribe = recorder.subscribe((state) => seen.push(state));

  recorder.transitionTo(VAD_STATE.INITIALIZING);
  unsubscribe();
  recorder.transitionTo(VAD_STATE.LISTENING);

  assert.deepEqual(seen, [VAD_STATE.INITIALIZING]);
});

test('a throwing subscriber does not break the others', () => {
  const recorder = createRecorder();
  const seen = [];

  recorder.subscribe(() => { throw new Error('bad subscriber'); });
  recorder.subscribe((state) => seen.push(state));

  recorder.transitionTo(VAD_STATE.INITIALIZING);

  assert.equal(seen.length, 1, 'the healthy subscriber still ran');
});

Testing messy API responses

Backends change shape. A normaliser is the boundary where you absorb that — and it's exactly where table-driven tests earn their keep.

normalise.js javascript 
// The server sometimes sends a boolean, sometimes a count, sometimes nothing.
// Normalise ONCE, at the edge — the rest of the app never worries about it.
export function activeRequests(health) {
  const active = health?.scheduler?.active;

  if (typeof active === 'boolean') return active ? 1 : 0;
  if (typeof active === 'number' && Number.isFinite(active)) return active;
  return 0;
}

export function supportsCacheSlots(health) {
  // Only advertise the capability when the server actually declares it
  return typeof health?.kv_slots === 'number' && health.kv_slots > 0;
}

Test the null and undefined paths explicitly

The three assertions for null, undefined and a missing object are the ones that will actually fail in production. "It's always defined" is the assumption every outage is built on.

The assertion that matters most

busyPercent returning 0 instead of NaN for a zero-delta sample is the kind of test that only exists because someone shipped a NaN% to a dashboard. Every bug you fix deserves a test that would have caught it.

  • Test state machines against their transition table, including the illegal moves.
  • Normalise at the boundary, table-test the normaliser.
  • Assert the null/undefined/empty paths by name.
  • Every production bug becomes a regression test.

Advanced patterns checkpoint

1. Why does the audio recorder attach a session token to every callback?

Correct answer: B. A microphone fires events asynchronously, so a callback from the run you just stopped can arrive after the next one started. The token makes those stale callbacks inert.

2. In a render loop, why multiply movement by delta?

Correct answer: B. A fixed amount per frame makes the simulation run faster on a faster display. Expressing velocity per second and scaling by the frame time makes the result refresh-rate independent.

3. A renderer asks your Electron main process to save a file named ../../.ssh/authorized_keys. What stops it?

Correct answer: C. contextIsolation protects the bridge, not the payload — and path.join will happily follow ... Every value arriving over IPC is untrusted input and must be validated in the main process, where the filesystem access actually happens.

What you can do now

You can structure an Electron app so the renderer can't reach the filesystem, model an async lifecycle as a state machine that rejects impossible transitions, drive a canvas animation that behaves identically on every display, wire a long-running daemon so each piece is testable and self-limiting, validate input at every boundary, and write tests that would actually catch the bugs you've already met.
